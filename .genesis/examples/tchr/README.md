# Exemplo: tchr

> Este diretório mostra como ficaria o **estado inicial** de um projeto real usando o `project-genesis-boilerplate`. **Não é código real do tchr** — é uma simulação do que três documentos do diretório `docs/` se pareceriam após uma primeira rodada de mentoria.

O `tchr` foi escolhido como caso porque é o projeto pessoal do criador deste boilerplate: uma plataforma de gestão educacional combinada com marketplace de cursos. Esse exemplo serve apenas como inspiração.

## Documentos inclusos

- `product-vision.md` — visão preenchida para o tchr.
- `problem-statement.md` — problema com evidências e custos do não-resolver.
- `technology-decision.md` — três opções de stack avaliadas (Node, Elixir, Go), recomendação justificada.

## Importante

- Estes arquivos **não** ficam em `docs/` do seu projeto. Eles vivem em `examples/` para servir de referência.
- Quando você for clonar este boilerplate para um projeto novo, **apague** `examples/` antes de começar — para não confundir com a documentação real.
- Os números, personas e decisões aqui são **ilustrativos** e podem estar desatualizados em relação ao tchr real.

## Como usar este exemplo

1. Leia os três arquivos para entender o nível de profundidade esperado.
2. Compare com os templates em `docs/` (que estão "vazios" propositalmente).
3. Use como benchmark de qualidade — o que está preenchido aqui é o tipo de coisa que a mentoria deve te ajudar a chegar.

## Próximo passo na vida real

Depois de absorver esse exemplo:

1. Apague `examples/`.
2. Limpe o conteúdo dos docs em `docs/` (mantendo a estrutura).
3. Abra o Claude Code e diga "vamos iniciar o projeto".
4. A mentoria começa.
