# User interviews

> Repositório de entrevistas com usuários reais. Entrevista mal feita é pior que nenhuma — vira viés de confirmação.

## Princípios

1. **Ouça mais do que fale.** Razão ouvido/boca ≥ 80%.
2. **Pergunte sobre o passado.** "Como você fez X da última vez?" é melhor que "Você usaria X?".
3. **Não venda.** Hipótese a validar não é hipótese pra defender.
4. **Anonimize.** Use pseudônimo, registre só o necessário.
5. **Conte falhas.** Entrevistas que refutam premissas valem mais que as que confirmam.

## Estrutura recomendada (15 min)

| Bloco | Tempo |
|-------|-------|
| Apresentação curta + consentimento | 1 min |
| Contexto da pessoa | 2 min |
| Como faz hoje (problema na vida real) | 5 min |
| Tentativas anteriores | 2 min |
| Disposição a mudar e a pagar | 3 min |
| Encerramento | 2 min |

## Roteiro base

### Aquecimento
1. Me conta um pouco do seu dia a dia.
2. Quais ferramentas você usa para \<área\>?
3. Quando foi a última vez que algo deu errado nisso?

### Problema
4. Como você lidou com isso?
5. Quanto tempo gastou?
6. Quanto isso custou (dinheiro ou energia)?

### Solução atual
7. O que você usa hoje?
8. O que funciona bem?
9. O que te incomoda?
10. Por que ainda usa isso?

### Disposição a mudar
11. Se existisse uma solução que \<benefício\>, você trocaria?
12. O que precisaria acontecer para você trocar?
13. Quanto valeria isso para você por mês?

### Encerramento
14. Tem mais alguém que sofre disso que eu deveria conversar?
15. Posso te avisar quando lançar para você testar?

## Anti-perguntas (não fazer)

- "Você usaria isso?" → não preditivo.
- "Quanto pagaria?" sem âncora → fantasia.
- "O que acha dessa feature?" → opinião sem custo.
- Perguntas tendenciosas com adjetivos.
